# Lab2_Algos
 Обоснование выбора:
 Для хранения остановок выбран динамический массив, а не LinkedList по следующим причинам:
 
 1. Доступ по индексу (O(1) против O(n) в LinkedList):
       - Метод get_bus_position_after_n_stops() требует прямого доступа к остановке по номеру n. Список даёт мгновенный доступ за O(1).
       - В LinkedList пришлось бы проходить n элементов, что медленнее.
  
  2. Добавление в конец (амортизированное O(1)):
       - Остановки добавляются последовательно в конец маршрута.
       - Динамический массив эффективен для этой операции.
  
  3. Обход всех элементов (O(n) для обеих структур):
       - display_route() и build_reverse_route() обходят все остановки.
       - Обе структуры линейны по времени, разницы нет.
  
  4. Память и локальность:
       - Список хранит элементы непрерывно в памяти, что даёт лучшую кэш-локальность и скорость итерации.
       - LinkedList требует дополнительной памяти на указатели (next/prev).
  
  5. Встроенная поддержка в Python.
    
  Вывод: динамический массив оптимален для данного сценария, так как приоритетными операциями являются доступ по индексу и добавление в конец.
